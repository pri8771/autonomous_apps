# Delivery Roadmap

## Phase 0 — Contracts

Define project, requirement, task, event, role, agent run, evidence, change request, and planning error schemas.

## Phase 1 — Project graph

Create projects, requirements, features, tasks, dependencies, plan versions, readiness calculations, and graph visualization.

## Phase 2 — Agent run lifecycle

Add roles, model configurations, context assembly, run creation, streaming logs, cancellation, retry, and schema-valid outputs.

## Phase 3 — Git and CLI execution

Add repository connection, worktree creation, task branches, CLI subprocesses, timeouts, commits, artifacts, and cleanup.

## Phase 4 — Parallel scheduler

Add atomic task claims, leases, heartbeats, priorities, worker matching, WIP limits, and independently progressing workers.

## Phase 5 — Review and evidence

Fan completed work out to code review, tests, specification review, and conditional security or visual review.

## Phase 6 — Repair

Classify failures, generate repair work, enforce attempt limits, rerun verification, and escalate with evidence.

## Phase 7 — Communication

Add shared blackboard records, direct asynchronous messages, and bounded deliberation rooms.

## Phase 8 — Change management

Add change requests, impact analysis, policy decisions, atomic graph updates, and plan-version increments.

## Phase 9 — Configurable teams

Add role editor, agent counts, parent/subagent policies, model and effort selection, permissions, and team templates.

## Phase 10 — Local models

Add Ollama discovery and installation, hardware awareness, benchmarks, model health, and enforced local-only mode.

## Phase 11 — Workflow designer

Add sequential, parallel, fan-out, fan-in, conditional, approval, retry, deliberation, and subworkflow nodes.

## Phase 12 — Platform delivery

Add iOS/macOS execution, web previews, full regression, release candidates, and end-to-end benchmark projects.

## V1 release gate

The system must demonstrate true asynchronous parallel implementation, parallel independent review, bounded repair, formal change-request handling, plan updates without stopping unrelated work, and an evidence-backed final pull request.
